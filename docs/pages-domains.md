# Private custom domains

The presentation uses `https://scribyra.com/`; the application uses
`https://app.scribyra.com/`. Both are aliases for the same private GitLab Pages
release. The generated host router opens the appropriate shell. The application
also stays available at `https://scribyra-aca39a.gitlab.io/app/`.

## GitLab setup

In the Scribyra project's **Deploy → Pages**, add both custom domains and enable
automatic certificates for each. Keep Pages access restricted to project members
and the repository private. Do not enable a single primary-domain redirect:
both hostnames need to remain independently accessible.

Each domain produces a different public verification TXT value. Copy the complete
value beginning `gitlab-pages-verification-code=` from GitLab; explanatory text is
not a verification value.

Use automatic TTL. Replace incorrect verification TXT records with the actual
GitLab values. Do not flatten the `app` CNAME (disable flattening for all CNAMEs
if configured). No Cloudflare redirect, rewrite, Worker, cache, or origin rule is
required for these two DNS-only hosts. GitLab provides HTTPS and access control.
Existing rules for `telemetry.scribyra.com` are independent.

## Release and verification

`npm run build:pages` builds the legacy application and a small root shell, then
assembles `.pages`. The compiler files are stored once under `/app/core/busytex`;
the root shell reuses them. Local staging uses hard links without modifying build
inputs. CI publishes this artifact and registers its browser-app release link.

`ops/pages/domains.json` set `active: true` on November 6, 2026, after both domains
verified, certificates served consistently, and a browser verified presentation →
app, compilation and offline reload at `https://app.scribyra.com/`. Pages needs no
sign-in. Release and environment links now use that address. The hostname routing is already present in the artifact
so it can be checked before promoting those links.

Projects are browser-local and scoped to their origin. Export a project ZIP from
the old address and import it at the new address; changing domains does not move
browser storage. Preserve the old URL for that migration.

Browser coverage in `tests/browser/pages-domains.spec.js` uses two loopback
hostnames to exercise the real root app, compiler, and offline service worker.
`tests/browser/pages.spec.js` covers the legacy `/app/` release.
