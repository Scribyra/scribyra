### Delivered

`window.scribyra.agent` exists while a project is open. It registers nine `agent.*`
operations on the existing internal v2 dispatcher. `describe()` reports only
registered implementations, envelope/value versions, `experimental:true`, the
actual build identity, limits and `recipe:"agent.md"`. No `window.scribyra.v1` is
installed. Other feature namespaces are untouched and can register independently.

- Paginated tree reads bind continuation to the document revision. Source reads
  use stable file IDs and inclusive line ranges, including blank and unrendered
  lines; they scan line boundaries without allocating a whole-file line array.
  The default is 50 lines, maximum 200 lines / 8,192 UTF-16 units. Long ranges have
  offset continuation; callers retain the same line range and expected revision.
- Patches require an explicit expected revision and accept up to 20 scalar-safe
  ranges or unique literal find/replace edits. Rust checks payloads, permissions,
  before text, overlap and project size before one Yjs transaction. Invalid batches
  create neither partial source edits nor author records. Successful retries return
  the original receipt, including after later typing.
- Agent patches use `AgentOrigin`, persistent agent/owner author records and a
  change record. Each command has an isolated undo group; unopened edited files
  get undo managers before the mutation. Agent attribution is descriptive and
  forgeable, not authentication. Source undo preserves the provenance records;
  rich undo event history belongs to the history feature.
- Builds start immediately and return a session job ID. Polls expose bounded
  outcome/count/revision metadata, not logs or PDFs. Diagnostics paginate with
  optional bounded details. Busy errors never toggle another build; cancel targets
  only a known session job. Project close aborts work and revokes retained API
  references and retries. Eight build records and 128 mutation receipts are retained.
- PDF export triggers an ordinary browser download and returns metadata identifying
  the accepted build and stale state. Project result values are labelled
  `contentType:"project-data"`; this label does not sandbox arbitrary page scripts.

`web/project-operations.js` extracts the companion's exact scalar-safe chunk helper
and build-result projection. Both adapters retain the existing shared source-patch
validator and revision machinery. The companion keeps its v1 grants, origin,
base64 transport and diagnostic/export limits. No frozen crate gained a feature.

The served recipe now prefers these operations and gives short revision-checked
editing guidance. Its contract test evaluates all ten literal snippets, applies
per-operation result budgets, retains failed-build source-link and undo checks,
and exercises warm compilation/patching offline. The existing UI-surface checks
still verify Compile/Cancel states, blank-line order, warnings and scoped logs.
No UI name was changed and no existing test was skipped or weakened for a pass.
