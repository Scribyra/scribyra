## Making a link

The wire format is `#tex=` followed by unpadded RFC 4648 base64url of **gzip
compressed UTF-8 source bytes**. It carries source only, with no filename, project
identity, compiler option or multi-file envelope. The receiving browser always
opens an independent in-memory project named “TeX link scratch”, containing `main.tex`.
Existing projects keep their identities and contents, including when a link opens
in an already active project tab. Only accepted links become persistent projects;
leaving or replacing an unapproved scratch discards it.

The dependency-free Node helper [tex-link.mjs](tex-link.mjs) prints the link:

```sh
nix develop -c node docs/reorientation/tex-link.mjs http://127.0.0.1:4701/ docs/reorientation/tex-link-example.tex
```

An agent with another language can gzip the UTF-8 bytes, base64url encode the
compressed bytes, remove `=` padding and append the result to the actual **app**
URL (including its `/app/` path when applicable). Do not put source in a query
parameter. The helper/decoder round-trip is tested with Unicode, a UTF-8 BOM, empty
source and the source-size boundary; the browser suite opens helper-generated links.

The entry accepts at most **16,384 encoded characters** (12 KiB compressed) and
**65,536 decompressed UTF-8 bytes**. It checks the encoded limit before base64
decoding, reads gzip output incrementally and cancels expansion over the source
limit. Canonical base64url, gzip integrity, UTF-8 and NUL checks fail with fixed
messages that cannot echo link contents. Oversize messages suggest ZIP import.
Browser URL limits, messaging tools and link rewriting can impose smaller limits.

## Consent, privacy and compiler boundary

A visible banner identifies the scratch project and treats link contents as
untrusted. **Allow and compile** is the single explicit consent action; opening
the link never compiles automatically. Normal Compile, keyboard shortcuts, auto
compile and agent commands share the consent guard; isolated feature builds also
pass through it. The banner requires `event.isTrusted`, so `button.click()` and
dispatched DOM events cannot approve. This protects a person following a hostile
link from automatic compilation or storage. It is not a defence against an agent
already controlling the page: that agent can do anything the page can, and real
browser input clicking the banner is the intended R5 route. Approval outside the
agent-controlled DOM is not part of this threat model.

The document's `meta.texLinkOrigin` marker contains the literal `link`, so clones,
manual recovery and binary recovery copies inherit the consent requirement.
Every descendant and reopened scratch asks again, even if its parent was approved
or auto compile had previously been enabled. Earlier device-local UUID markers
are recognized on reopening and copied into document metadata. This marker is a
UI safeguard, not protection against arbitrary page scripts or source ZIP round
trips, which export ordinary source without project metadata.

The fragment is consumed and removed with `history.replaceState(null,...)` before
startup/telemetry and decoding, including for invalid or oversized input. It is
never persisted as a URL or encoded string, included in project metadata, or deliberately logged.
The **decoded source** stays in the active Y.Doc until a trusted **Allow and
compile** click saves it as ordinary project content, then grants compilation.
There is no project, head, journal, checkpoint, provenance preference or workspace
preference write for an unapproved new link, including after edits or recovery.
Local-tab synchronization starts after acceptance. Only one scratch is active;
rapid fragment changes retain at most one decode and one pending bounded entry.
Leaving, reloading or replacing an unapproved scratch destroys its document.
Recovery copies of a link also start in memory and require their own acceptance.
A failed initial save keeps the source in memory and compilation blocked, with a
retry action. HTTP never
receives URL fragments. Acceptance checks inspect requests, console messages,
history state, Web Storage, IndexedDB values/keys, cache request keys and enabled
local diagnostics for the fragment; diagnostics also exclude the source marker.
This does not erase a link from the sender's chat, clipboard or other applications.

The entry uses the existing browser-worker LuaLaTeX path without new compiler
options: `web/compiler.js` passes `shellEscape=false` and no shell handlers;
the pinned worker selects `--no-shell-escape`, and LuaLaTeX also gets `--nosocket`.
The existing `scribyraProjectWrites` canonical filesystem guard restricts engine
writes to the isolated virtual project and `/tmp`, with package/runtime sources
read-only and parent/symlink escapes denied. The browser hostile-source case tries
shell execution and an out-of-project write, then opens and compiles a clean link.
The existing compiler cancellation and 180-second execution budget still apply.
This is the existing worker policy, not an independent security audit.

## Browser-agent results

The existing experimental `window.scribyra.agent` contract suffices. After the
person allows compilation, `status().value.latestJobId` identifies the banner
build. Poll `poll({jobId,waitMs:25000})` until terminal; it returns status, pages,
warning/error counts and freshness without source, PDF bytes or full logs. Read
`diagnostics({jobId,limit:3})` for the top three bounded diagnostics.
`exportPdf()` initiates an ordinary PDF download and returns metadata, never
base64. A subsequent agent build uses `compile()` followed by the same polling.
The compact recipe remains served at `agent.md`, within its existing size budget.

Offline links need an already cached application shell and the compiler/packages
their source requires. A fresh device cannot fetch an uncached compiler offline.
The test warms a document, leaves the page, disables networking, opens a different
link through the service worker and compiles it after consent.
