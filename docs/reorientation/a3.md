# A3 agent recipe and contract

November 5, 2026. The app serves `public/agent.md` at its deployment base,
including `/app/agent.md` in the Pages release. The Vite head link substitutes
the deployment base, avoiding resolution against an incidental nested URL;
the custom-domain app router adds the equivalent relative root link. The recipe is documentation for the current DOM, with six executable
Playwright examples and no published command API or installed helper. It covers
tab identity, compile state, outcome, bounded issues and rendered source lines.
Project content and logs remain untrusted data. No indexing material, private
address, network destination or public-launch change was added.

The worker precaches the recipe, incorporates its bytes in the shell version,
and excludes it from the app-HTML navigation fallback. Pages assembly copies the
built recipe to the custom-domain root as well as the legacy app directory.
An offline navigation checks the rendered text and Markdown MIME type. A cache-miss navigation may fail
or return exact Markdown, but cannot return the app HTML. Browser offline
checks use Playwright’s offline control; additional browser HTTP caches may
still provide a response.

The optional “Use with an AI” button was omitted: the head link supplies discovery
without another visible control. The contract compares dashboard accessibility
snapshots before and after removing that link and requires identical bytes.
It also checks that the head link itself has an empty AI-mode snapshot.

## Contracts and limits

`tests/browser/agent-recipe.spec.js` reads the deployed Markdown, extracts all six
JavaScript examples and all four compile-state attribute/value literals, and
executes them against real successful and deliberately failed compiles of the
article and 100-page thesis. It checks title identity, warnings/pages, source
navigation and keyboard editing. Region budgets are UTF-8 bytes of Playwright
AI-mode accessibility snapshots: compile 150, status 300, issues 1,800, source
2,400 and the example source line 500. JSON attachments retain bytes, characters
and characters/4 token estimates. These measure scoped snapshots, excluding MCP
framing, tool schemas and polling; they do not establish model token savings.
CodeMirror virtualization and whitespace normalization still apply; raw
`textContent` preserves source whitespace. The existing surface spec verifies
blank-line ordering and missing-package attribution as well.

CI's existing `browser-pages` selection now includes both agent specs alongside
`pages.spec.js` and `pages-domains.spec.js`. Its wrapper generates the local ZIP
fixtures; agent specs use the assembled `/app/` when the Pages test URL is set.
The existing CI job runs Chromium only, with private closed-schema summaries;
it does not run Firefox, WebKit or a model trial. Local checks cover all engines.
No CI job, deployment, push, private service or external model was invoked here.

## Separate-agent trial setup

```sh
nix develop -c node scripts/agent-trial-setup.mjs --port=4474 --debug-port=4475 --fixture=thesis
```

This generates repository fixtures, builds production assets, starts a strict
loopback preview and Chromium with a disposable profile and remote debugging.
It imports the selected fixture, leaves its editor open, then prints the tab
URL/title, recipe URL and `--cdp-endpoint=http://127.0.0.1:4475` for another agent.
The script runs no model and does not compile the imported project. It rejects
occupied ports before building. Ctrl+C/SIGTERM closes its browser and its exact
owned preview process. Other profiles and preview servers are untouched.
Use `--headless` without a display; `--check` attaches a second Playwright client,
checks the imported title through CDP, then cleans up and exits. Fixtures are
`article`, `thesis` and `missing-package`. This is local test scaffolding, not a
Scribyra runtime dependency or evidence of attachment to the owner's existing tab.

The R4 attachment test and the A4 experiment remain open.

## Browser calibration and corrections

The first root matrix passed **16/18**, with two failures in the new offline
recipe test. Chromium decoded typographic punctuation incorrectly because the
static Markdown response had no charset; Firefox’s Playwright response-body
protocol read raised `NS_ERROR_INVALID_CONTENT_ENCODING`. The recipe is now
ASCII (including the description of the title separator), and the test compares
the actual rendered plaintext and response MIME type. Its equality assertion is
retained. WebKit passed that initial check.

The second root matrix passed **17/18**. Its extra cache-deletion test wrongly
required navigation to reject in every engine; Firefox returned valid Markdown
instead. The corrected assertion accepts a navigation error or exact Markdown,
and rejects app HTML in either case. The focused discovery rerun passed **3/3**.
All compile, warning, source, line and snapshot-budget cases passed in both root
matrices. The final contract also rechecks the title after each compile outcome.

## Local Pages acceptance

`npm run build:pages` passed both Vite builds and release assembly. The local
matrix passed **24/24**, eight per engine: both agent specs and both Pages specs.
This verifies the deployed `/app/` recipe with real compilation and offline
reload, plus the custom-domain root recipe. It used this exact local harness
(invoked with `nix develop -c bash tmp/a3-pages-check.sh`):

```sh
set -euo pipefail
ulimit -c 0
test ! -e tmp/a3-root-dist
test ! -e .cache/a3-pages-app-dist
mv dist tmp/a3-root-dist
pages_pid=''
cleanup() {
 if test -n "$pages_pid"; then
  kill -TERM "$pages_pid" 2>/dev/null || true
  wait "$pages_pid" 2>/dev/null || true
 fi
 if test -d dist; then mv dist .cache/a3-pages-app-dist; fi
 mv tmp/a3-root-dist dist
}
trap cleanup EXIT
npm run build:pages
python3 -m http.server 4474 --bind 127.0.0.1 --directory .pages > tmp/a3-pages-server.log 2>&1 &
pages_pid=$!
SCRIBYRA_TEST_PORT=4474 SCRIBYRA_TEST_PAGES_URL=http://127.0.0.1:4474/ PLAYWRIGHT_JSON_OUTPUT_NAME=tmp/a3-pages.json __EGL_VENDOR_LIBRARY_FILENAMES=/nix/store/j6846pd6a2i4bx16wcdn571sq7jznr71-mesa-26.2.6/share/glvnd/egl_vendor.d/50_mesa.json LIBGL_ALWAYS_SOFTWARE=1 npx playwright test tests/browser/agent-recipe.spec.js tests/browser/agent-surface.spec.js tests/browser/pages.spec.js tests/browser/pages-domains.spec.js --project=chromium --project=firefox --project=webkit --workers=2 --reporter=list,json --output=tmp/a3-pages
```

The harness killed only its recorded Python child PID, waited for it, retained
the assembled app build under `.cache/`, and restored the root `dist` even on
failure. The domain spec owns and closes its own ephemeral local servers.
The Pages run began before the extra post-compile title assertion was added;
the subsequent root recipe run covers the final recipe test on every engine.

The initial root commands used the same Mesa/port settings as the final command,
both agent spec paths, `--workers=2 --reporter=list,json`, and respectively
`PLAYWRIGHT_JSON_OUTPUT_NAME=tmp/a3-browser.json --output=tmp/a3-browser` and
`PLAYWRIGHT_JSON_OUTPUT_NAME=tmp/a3-browser-final.json --output=tmp/a3-browser-final`.
